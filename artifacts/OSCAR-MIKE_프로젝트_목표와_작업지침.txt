OSCAR-MIKE 프로젝트 목표 및 작업 지침 요약
작성일: 2026-11-10

1. 게임의 주제와 목표
- Lethal Company 스타일의 최대 4인 협동 FPS 파밍 게임.
- Unity 6000.3.9f1 + URP 사용.
- Steam/Epic 등 여러 플랫폼을 고려하며 특정 스토어에 종속되지 않는 구조.
- 호스트가 이동, 상호작용, 게임 상태를 최종 판정.
- 확인한 문서에는 구체적인 세계관, 스토리, 미술 분위기는 명시되지 않음.

2. 반드시 유지해야 하는 기본 흐름
메인 메뉴 → 로비 → 게임 맵
- 4인 접속과 플레이어 생성 유지.
- 준비 상태 공유 및 모든 참가자 준비 후 호스트만 게임 시작.
- NGO 네트워크 씬 전환으로 참가자들이 함께 이동.
- 호스트 이탈 및 종료 시 안전한 처리.

3. 주요 작업 지침
- 구현 전에 AGENTS.md를 다시 확인한다.
- 기존 구조를 보존하고 작은 단위로 확장한다.
- 현재 작업에서 사용자 작성·수정 코드임이 명확하지 않은 스크립트는 직접 수정하지 않고 별도 컴포넌트 추가를 우선한다.
- 기존 클래스가 지원할 때만 C# partial을 사용한다.
- 네트워크/UI 흐름 변경 후 씬 전환, 4인 스폰, 호스트 이탈, 참가 코드 표시를 검증한다.
- 모든 UI 문구는 한국어로 작성하고 Pretendard 폰트를 사용한다.
- 네트워크는 NGO + UTP + UGS Multiplayer를 사용한다. Mirror 및 standalone Lobby/Relay 혼용을 피한다.
- 입력은 해당 플레이어의 소유 클라이언트만 처리한다.
- NetworkVariable 쓰기 권한은 서버에 둔다.
- 입력 액션 맵 이름은 Keyboard&Mouse를 유지한다.
- 싱글턴은 Instance + DontDestroyOnLoad 구조를 유지한다.

4. 등록된 MVP 개발 과제
Ticket 1 — 준비 상태 동기화
  준비/취소 공유, 호스트 시작 제한, 늦게 참가한 클라이언트의 상태 수신.
Ticket 2 — 파밍 상호작용 동기화
  줍기, 놓기, 소유권 변경 및 동시 상호작용 시 중복 획득 방지.
Ticket 3 — 격자 인벤토리
  타르코프식 배치, 회전, 분할 및 서버의 겹침·범위 검증.
Ticket 4 — 세션 안정화
  생성, 참가, 나가기, 재접속 및 잘못된 코드·만료·풀방·연결 끊김 처리.
Ticket 5 — 회귀 검증 체계
  반복 가능한 체크리스트, 실행 절차, 릴리즈 검증 기준 마련.

권장 순서
- Ticket 1 이후 Ticket 4의 이벤트 안정화 일부를 병행.
- Ticket 2와 Ticket 3에 공통으로 사용할 호스트 검증 패턴 정리.
- Ticket 5는 각 티켓 완료 시 함께 갱신.

주의: 티켓 문서에 완료 표시가 없으므로 등록된 과제가 모두 미완료라고 단정할 수 없다.

5. 문서화된 적 AI 방향
- 순찰 → 소리 조사 → 시각 발견 시 경고 → 전투.
- 경고 중 근처 증원 구역에 지원 요청.
- 걷기, 달리기, 웅크리기, 엎드리기의 소리 감지 거리 구분.
- 소리만 감지한 경우 위치를 조사하며, 직접 발견 전에는 경고·사격하지 않음.
- 모든 판단, 이동, 소리 감지, 증원 생성은 서버 권한으로 처리.
- 실제 탄환, 명중, 체력, 사격 효과는 문서상 범위 밖.
- AI 전용 테스트의 UTP 직접 접속은 제품의 UGS 세션 흐름을 대체하지 않음.

6. 검증 기록과 현재 상태
- AI 문서에는 2026-10-02 통합 검증 41항목 통과 기록이 있음.
- 기존 메인 메뉴/로비 흐름 및 실제 입력 발소리 회귀 검증은 수동 항목으로 남아 있음.
- 요약 작성 시 게임 실행이나 코드 검증은 수행하지 않았음.
- 확인 당시 이 채팅에 별도로 등록된 진행 중 자동 목표는 없었음.
